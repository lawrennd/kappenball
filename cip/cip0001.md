# CIP-0001: Migrate from MATLAB to Python + Jupyter Notebooks

> **Note**: This CIP describes HOW to modernize Kappenball from 2012 MATLAB code to 2026 Python + Jupyter.

## Status

- [x] Proposed - Initial idea documented
- [x] Accepted - Approved, ready to start work
- [x] In Progress - Actively being implemented
- [ ] Implemented - Work complete, awaiting verification
- [ ] Closed - Verified and complete
- [ ] Rejected - Will not be implemented
- [ ] Deferred - Postponed

## Summary

Migrate the Kappenball physics simulations (billiards and falling ball demos) from MATLAB to Python + Jupyter notebooks. This modernization makes the educational code accessible to students without expensive licenses, while maintaining the interactive, visual nature of the original demonstrations.

## Tenet Alignment

This CIP directly supports all three project tenets:

- **Uncertainty Accessible**: Python's visualization libraries (matplotlib, plotly) provide excellent tools for making uncertainty visible
- **Interactive Engagement**: Jupyter widgets (ipywidgets) enable interactive controls similar to MATLAB's UI, maintaining the "play with uncertainty" experience
- **Easy to Modify**: Python is free, widely available, and beginner-friendly - students can go from running to modifying in minutes

## Motivation

The original 2012 MATLAB code presents barriers for modern educational use:

1. **License cost**: MATLAB requires expensive licenses that many students don't have
2. **Installation complexity**: Full MATLAB installation is large and complex
3. **Limited sharing**: MATLAB code can't easily be shared or run on the web
4. **Accessibility**: Python has become the lingua franca of scientific computing and data science

Python + Jupyter notebooks solve these issues while maintaining (and potentially improving) the interactive, visual learning experience.

## Detailed Description

### Target Architecture

**Core components:**
- Python 3.10+ for physics simulation code
- NumPy for numerical computations (replaces MATLAB arrays)
- Matplotlib for visualization (replaces MATLAB plotting)
- Jupyter notebooks for interactive demonstrations
- ipywidgets for interactive controls (replaces MATLAB UI callbacks)

**Project structure:**
```
kappenball/
├── notebooks/
│   ├── entropy_billiards.ipynb    # Port of demEntropyBilliards.m
│   ├── falling_ball.ipynb         # Port of demKappenBall.m
│   └── examples/                  # Additional examples
├── kappenball/                    # Python package
│   ├── __init__.py
│   ├── billiards.py              # Port of simulateBilliards.m, etc.
│   ├── falling_ball.py           # Port of simulateFallingBall.m
│   ├── physics.py                # Core physics utilities
│   └── visualization.py          # Plotting utilities
├── tests/                        # Unit tests
├── requirements.txt              # Python dependencies
└── README.md                     # Updated instructions
```

### Migration Strategy

**Phase 1: Core Physics Engine**
- Port physics simulation functions (no UI)
- Maintain numerical accuracy (verify against MATLAB)
- Create unit tests to ensure correctness

**Phase 2: Visualization Layer**
- Port plotting functions to matplotlib
- Recreate visual style of original demos
- Ensure clarity of uncertainty visualization

**Phase 3: Interactive Notebooks**
- Create Jupyter notebooks with ipywidgets controls
- Implement keyboard interactions where possible
- Add markdown explanations for lecture context

**Phase 4: Documentation & Examples**
- Write installation instructions
- Create tutorial notebooks
- Document API for students who want to extend

## Implementation Plan

1. **Setup Python Package Structure**:
   - Create `kappenball/` package directory
   - Set up `setup.py` or `pyproject.toml`
   - Define minimal dependencies in `requirements.txt`

2. **Port Core Physics (billiards simulation)**:
   - Port `initializeBilliards.m` → `billiards.py::initialize()`
   - Port `simulateBilliards.m` → `billiards.py::simulate()`
   - Port `vectorBilliards.m` → `billiards.py::compute_vectors()`
   - Create unit tests comparing outputs to Octave reference (if demos run successfully)
   - Note: First verify original code runs in Octave (`brew install octave`)

3. **Port Falling Ball Physics**:
   - Port `simulateFallingBall.m` → `falling_ball.py::simulate()`
   - Port related callback functions
   - Create unit tests

4. **Create Visualization Layer**:
   - Design matplotlib-based plotting functions
   - Match visual style of MATLAB demos
   - Add animation capabilities using matplotlib.animation

5. **Build Interactive Notebooks**:
   - Create `entropy_billiards.ipynb` with ipywidgets controls
   - Create `falling_ball.ipynb` with keyboard/button interactions
   - Add markdown cells explaining uncertainty concepts

6. **Testing & Validation**:
   - Verify numerical accuracy against MATLAB
   - Test interactive features
   - Get feedback from students/educators

7. **Documentation**:
   - Update README with Python installation instructions
   - Add notebook-level documentation
   - Create API documentation for extension

## Backward Compatibility

**MATLAB code preservation:**
- Keep original MATLAB code in `matlab/` directory
- Document as "reference implementation"
- Useful for numerical verification with GNU Octave

**Octave for verification:**
- Use GNU Octave (free, `brew install octave`) to run original code
- Octave is largely MATLAB-compatible and sufficient for testing
- No MATLAB license required for development or verification

**No breaking changes:**
- This is a parallel implementation, not a replacement
- Users with MATLAB/Octave can continue using original code

## Testing Strategy

1. **Numerical Accuracy Tests**:
   - Compare Python outputs to Octave reference runs (original MATLAB code)
   - Install Octave: `brew install octave` (free, MATLAB-compatible)
   - Use pytest with numpy.testing for array comparisons
   - Tolerance: 1e-10 for deterministic physics
   - If Octave incompatibilities arise, document as "Python reference implementation"

2. **Visual Regression Tests**:
   - Generate plots from both systems (Python vs Octave)
   - Visual inspection during development
   - Ensure uncertainty concepts remain clearly visible

3. **Interactive Tests**:
   - Manual testing of notebook interactions
   - Automated widget state testing with pytest

4. **Installation Tests**:
   - Test on clean Python environments
   - Verify on multiple platforms (macOS, Linux, Windows)
   - Ensure "from running to modifying in minutes" tenet is met
